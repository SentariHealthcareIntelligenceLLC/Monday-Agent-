# Live state as found — 2026-09-02

Read-only audit of the **Monday Agent** project (`xziunvsgzriuufcfdkvx`). Recorded because
the live database does **not** match the pack in `docs/migration-pack/`.

## Steps already complete

Step 02 is **done**. All 21 tables exist with RLS enabled and zero rows; step-06 queries 1
and 2 pass (five new tables RLS-on, all five views `security_invoker = true`).

## The database is a later generation than this repo

The live project was migrated on 2026-09-02 08:13–08:15 UTC from a **different, later**
build of the pack. Differences:

| | Pack in this repo | Live database |
|---|---|---|
| Role helpers | `app_current_role`, `app_is_admin`, `app_current_person_id` | `current_app_role`, `is_dashboard_admin`, `current_person_id` |
| Migration names | `20260901000001…3` | `20260902081325…20260902081530` |
| Extra view | — | `v_wa_delivery_summary` |
| Extra trigger helper | — | `touch_wa_contact_window` |
| Extra migration | — | `harden_function_grants` |

**Consequence:** applying this repo's migrations to the live project would create a second,
parallel set of role-helper functions and rewrite every policy to point at them. The
policies are semantically equivalent, so the dashboard would still work, but the database
would carry two naming generations at once.

**The sharper problem, now fixed:** `003_auth_profiles.sql` defines `touch_updated_at()`
with no pinned `search_path`. `CREATE OR REPLACE` over the hardened live version would
silently strip the `SET search_path = public, pg_temp` that `harden_function_grants`
added. `005_harden_function_grants.sql` closes this — it re-pins the search_path and
re-applies the REVOKEs for both naming generations, and must stay last in the sequence.

## Recommendation

Reconcile before running anything else against the live project: either regenerate this
repo's migrations from the live schema (`supabase db pull`), or accept the duplication
knowingly. Do not run `supabase db push` or `npm run migrate` against
`xziunvsgzriuufcfdkvx` until that is decided — nothing in the repo is a prerequisite for
the app running, since the live schema is already ahead.
